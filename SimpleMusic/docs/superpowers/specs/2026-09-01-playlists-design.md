# DiskTone 播放列表设计

日期：2026-09-01

## 目标

在不改变现有资料库、搜索、播放器和导航层级的前提下，允许用户新建播放列表，并把系统音乐库或本地下载的歌曲加入其中。播放列表中的歌曲继续交给现有 `PlaybackCoordinator` 播放。

## 范围与边界

- 资料库分类区新增“播放列表”入口；不新增 Tab。
- 用户可以新建、重命名和删除播放列表。
- 歌曲的“更多”菜单新增“加入播放列表”；一个歌曲可加入多个播放列表，重复加入同一列表不创建重复记录。
- 系统音乐与已下载歌曲都能加入播放列表；删除本地文件后，该歌曲从受影响的播放列表中自动消失。
- 本次不新增独立“喜欢”开关、不提供跨设备同步、不支持手动拖动排序。

## 数据模型与迁移

Core Data 新增：

- `PlaylistEntity`：稳定 ID、名称、创建时间、更新时间。
- `PlaylistItemEntity`：稳定 ID、歌曲 ID、加入时间、顺序值，并关联一个 `PlaylistEntity`。

不复制 `MusicTrack` 的元数据；列表项只保存歌曲 ID。显示和播放时从现有统一资料库解析歌曲，因此系统库元数据更新和下载歌曲元数据保持单一来源。

新增一个模型版本，使用轻量迁移。旧的下载歌曲记录与 `sourceURL` 等字段保持不变。

## 交互与导航

资料库 → 播放列表：

- 页面顶部显示“新建播放列表”按钮。
- 每个播放列表显示名称和歌曲数量。
- 轻点进入歌曲列表；页面继续复用现有 `TrackListViewController` 的播放、全部播放和随机播放能力。
- 长按或“更多”操作提供重命名与删除。删除列表只删除列表和列表项，不删除歌曲文件或系统媒体。

歌曲行的更多操作：

- 本地歌曲继续保留“删除本地歌曲”。
- 新增“加入播放列表”，弹出当前列表选择界面；若尚无列表，可在弹窗中直接新建后加入。
- 系统歌曲此前没有更多入口；本次为它提供仅包含“加入播放列表”的入口。

## 数据流

`PlaylistStore` 负责 Core Data 读写与歌曲 ID 去重；`PlaylistViewModel` 将列表项解析成 `MusicTrack`，并订阅现有 `LibraryViewModel` 的统一歌曲流。资料库和搜索将歌曲的更多操作交给同一 `PlaylistStore`，避免把列表逻辑散落到多个控制器。

当资料库刷新、权限变化或本地文件被删除后，列表页重新解析歌曲 ID，找不到的条目不会展示，并会异步清理失效的列表项。

## 错误处理

- 空名称、仅空白名称或重名：不创建列表，显示本地化输入提示。
- Core Data 保存失败：保留当前页面数据并显示可理解的错误提示，不影响现有播放。
- 播放列表为空：显示空状态，禁用全部播放与随机播放。
- 条目歌曲已不可用：不播放该条目，清理失效引用而不影响其余歌曲。

## 验证

- `PlaylistStore` 测试：新建、重命名、删除、重复加入去重、关系清理与轻量迁移。
- `PlaylistViewModel` 测试：歌曲 ID 解析、资料库刷新、缺失歌曲清理。
- UIKit 测试：资料库入口、新建流程、歌曲更多菜单、加入、播放列表播放以及空状态。
- 最终运行相关 focused XCTest、完整 XCTest、generic iOS Simulator/device build。

## 不在本次范围

- “我喜欢的音乐”自动收藏列表。
- 手动拖动排序、封面编辑、共享或云同步。
- 对系统媒体库或下载文件本身的删除策略改动。
