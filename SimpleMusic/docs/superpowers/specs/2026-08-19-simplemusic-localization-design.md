# SimpleMusic 英文、简体中文与繁体中文本地化设计

日期：2026-08-19

## 目标

为现有 SimpleMusic UIKit 应用补齐英文、简体中文和繁体中文本地化。应用始终跟随 iOS 系统语言，不提供应用内语言切换入口。

英文是工程开发语言和默认回退语言。系统首选语言为简体中文时使用简体资源，为繁体中文时使用繁体资源；系统不支持的其他语言回退到英文。

本次覆盖所有用户可见内容，包括页面标题、按钮、提示、错误信息、播放状态、动态数量、无障碍标签、应用名称和系统权限说明。

## 非目标

- 不增加设置页语言选择器，也不在应用运行期间热切换语言。
- 不本地化代码注释、调试日志、测试方法名称和不会展示给用户的 `fatalError`。
- 不改变播放、下载、资料库、权限或导航业务行为。
- 不增加简体中文、繁体中文和英文以外的语言。

## 语言与品牌名称

应用使用以下本地化标识：

| 资源区域 | 应用名称 | 用途 |
| --- | --- | --- |
| `en` | `DiskTone` | 开发语言、英文界面及默认回退 |
| `zh-Hans` | `听见` | 简体中文界面 |
| `zh-Hant` | `聽見` | 台湾常用繁体中文界面 |

繁体翻译采用台湾常用措辞，例如“資料庫”“設定”“藝人”“音訊”“本機”，不采用机械的简繁字符转换。

## 资源结构

在 App target 中增加三组 `Localizable.strings`：

```text
SimpleMusic/
  en.lproj/Localizable.strings
  en.lproj/Localizable.stringsdict
  zh-Hans.lproj/Localizable.strings
  zh-Hans.lproj/Localizable.stringsdict
  zh-Hant.lproj/Localizable.strings
  zh-Hant.lproj/Localizable.stringsdict
```

三种语言各自增加 `InfoPlist.strings`，至少本地化：

- `CFBundleDisplayName`
- `NSAppleMusicUsageDescription`

工程 `developmentRegion` 保持为 `en`，`knownRegions` 明确登记 `en`、`zh-Hans`、`zh-Hant` 和现有 `Base`。`Base.lproj` 中的 LaunchScreen 继续保留，不复制三套启动页。

`Info.plist` 中的基础权限说明改为英文，确保资源缺失或系统语言不受支持时仍得到正确英文说明。

## Key 与代码接入

本地化 key 使用稳定的语义命名，不把中文原文当作 key。例如：

- `library.title`
- `player.now_playing`
- `download.failure.invalid_url`
- `accessibility.open_settings`

新增小型 `L10n` 工具统一读取 `Localizable.strings` 和格式化参数。普通文案通过语义 key 获取；包含歌曲名、百分比、队列位置或错误参数的文案使用格式化 key，不在界面代码中按语言拼接句子。

所有三套 `Localizable.strings` 必须拥有完全一致的 key。英文资源必须完整，任何缺少的非英文资源由系统按开发语言规则回退英文。

## 数量与格式化文本

歌曲数量等存在英文单复数差异的文案使用标准 `Localizable.stringsdict`：

- 英文：`1 song`、`2 songs`
- 简体中文：`1 首`、`2 首`
- 繁体中文：`1 首`、`2 首`

队列位置、下载进度和包含歌曲名的句子使用位置参数。三种语言的参数数量和类型必须一致，翻译可以调整参数顺序。

## 本地化覆盖范围

生产代码中的以下内容全部接入本地化资源：

- 首次授权页和音乐资料库权限说明。
- iPhone Tab、iPad 侧栏、播放器引导和页面导航标题。
- 资料库分类、状态提示、空状态、歌曲数量及本地删除确认。
- 搜索标题、占位符、无结果状态和无障碍说明。
- 迷你播放器、全屏播放器、iPad 播放面板、队列和播放控制无障碍标签。
- 下载输入、下载中、成功、失败、取消、重试及错误原因。
- 设置、关于、权限状态、下载选项和说明文案。
- 用户可见的持久化或本地文件降级提示。
- `MusicTrack` 的未知艺人、未知专辑等展示兜底。

内部注释和诊断信息继续使用现有语言，避免把开发者文本混入翻译资源。

## 系统语言变化

应用不维护自定义语言状态。启动时由 `Bundle.main` 按 iOS 首选语言选择资源。用户在系统设置中更改语言后，由 iOS 结束或重新启动应用并重新加载资源；应用不注册运行时语言变化观察者。

这保证页面创建、通知权限文案和系统桌面名称均遵循同一语言来源，不产生部分页面即时切换、部分页面仍为旧语言的混合状态。

## 测试策略

新增本地化资源测试，验证：

- `en`、`zh-Hans`、`zh-Hant` 三套普通文案 key 完全一致。
- 三种语言的格式化占位符数量和类型一致。
- 英文、简体和繁体资源可由各自 `.lproj` bundle 正确读取。
- 英文单复数以及简繁中文数量格式符合预期。
- 三套 `InfoPlist.strings` 均包含正确的应用名称和权限说明。
- 工程开发语言为英文，已登记三种受支持语言。

现有行为测试不固定依赖当前模拟器语言。测试页面状态和交互时使用对应本地化 key；翻译的实际字面内容由独立资源测试验证，避免同一行为测试只能在某一种系统语言下运行。

## 验证策略

完成实现后执行：

1. 全量 XCTest。
2. generic iOS Simulator 构建。
3. generic iOS device 构建。
4. 分别以英文、简体中文和繁体中文启动应用。
5. 在 iPhone 和 iPad 检查首页、资料库、搜索、播放器、下载和设置主要页面。
6. 检查构建产物中的本地化资源、应用名称和权限说明。

模拟器启动检查覆盖主要界面文案和明显截断；系统音乐真实授权弹窗仍以真机发布前检查为准。

## 完成标准

- 系统为英文时，所有用户可见内容显示自然英文，应用名称为 `DiskTone`。
- 系统为简体中文时，所有用户可见内容显示简体中文，应用名称为“听见”。
- 系统为繁体中文时，所有用户可见内容显示台湾常用繁体中文，应用名称为“聽見”。
- 系统使用其他语言时完整回退英文，不显示本地化 key 或混合语言。
- 三种语言的动态参数、数量、权限说明和无障碍标签正确。
- 全量测试及模拟器、设备构建通过，播放和下载行为没有变化。
